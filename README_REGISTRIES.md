# MAVIS — еженедельный автопарсинг реестров

## Новая схема

1. Один раз в неделю локальный скрипт запускается на рабочем Mac.
2. Каждый реестр выгружается целиком в `data/<source>.json`.
3. Перед заменой рабочей базы проверяются количество записей и качество ключевых полей.
4. Пустой, резко уменьшившийся или неверно распознанный результат не публикуется: сохраняется предыдущая рабочая версия.
5. После `git push` приложение сразу ищет по готовым JSON-снимкам. Менеджерам не нужно расширение Chrome и не нужно ждать открытия сайтов.

## Что уже подготовлено

- `scripts/run_weekly.py` — общий запуск, резервная копия, валидация, логи и публикация;
- `scripts/registry_sources.json` — единый список 8 реестров + реестр специалистов;
- исправленная базовая логика парсеров старого/нового СПК и действующих аттестатов;
- защита ISO-парсера от перезаписи рабочей базы пустым JSON;
- `scripts/install_macos_schedule.sh` — установка запуска каждый понедельник в 06:00;
- фронтенд переведён на моментальный поиск по опубликованным снимкам;
- GitHub Actions больше не парсит белорусские сайты: он только проверяет изменённые JSON.

## Первый ручной запуск на Mac

```bash
cd /путь/к/клонированному/mavis-kp-generator
python3 -m venv .venv
source .venv/bin/activate
pip install -r scripts/requirements.txt
python3 scripts/run_weekly.py
```

Сначала запускайте без `--publish`. Проверьте итог и логи в папке `logs/`. Затем:

```bash
python3 scripts/run_weekly.py --publish
```

Для публикации репозиторий должен быть именно клонирован через Git, а `git push` должен уже работать через SSH или GitHub CLI. Токен GitHub не нужно хранить в приложении или расширении.

## Автозапуск на Mac

```bash
bash scripts/install_macos_schedule.sh
```

Проверка задания:

```bash
launchctl print gui/$UID/by.mavis.registry-weekly
```

Ручной тест задания:

```bash
launchctl kickstart -k gui/$UID/by.mavis.registry-weekly
```

## Реестры со сложным JavaScript

Для ISO/СУОТ, сертификатов на металл и лицензий добавлен диагностический сборщик браузерных ответов:

```bash
pip install 'playwright>=1.40,<2'
# Скрипт использует установленный Google Chrome; отдельная загрузка Chromium не нужна.
python3 scripts/capture_browser.py --sources iso metal lic --wait 45
```

Он открывает официальные страницы в постоянном профиле Chrome и сохраняет HTML, скриншоты и JSON-ответы в `snapshots/`. Он не обходит CAPTCHA. По этим снимкам нужно дописать три нормализатора до формата приложения.

## Важно перед публикацией

В исходном `index.html` находится открытый входящий webhook Bitrix24. Если репозиторий публичный или архив кому-либо передавался, webhook нужно отозвать в Bitrix24 и вынести из клиентского кода. Это отдельная задача, чтобы не сломать генератор КП при текущей переработке реестров.


## Состояние исходных данных из старого проекта

При аудите старые снимки `spk.json`, `spk2.json`, `att.json`, `attoff.json` и `iso.json` не прошли проверку качества. Они перенесены в `quarantine/legacy-invalid-data/` и не используются приложением. До первого успешного локального обновления соответствующие реестры будут отображаться как недоступные, а не как «ничего не найдено». Рабочим в исходном архиве признан только снимок ОСП.

Результаты проверок компаний и история поиска в режиме «Реестры» не сохраняются в браузере. Сохраняются только пользовательские настройки выбранного профиля реестров.
